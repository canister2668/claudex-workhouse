# 既知の制限

[English](known-limitations.en.md) · [한국어](known-limitations.ko.md) · [日本語](known-limitations.ja.md)

前へ: [テスト](testing.ja.md) · [ガイドブック](guide.ja.md) · 次へ: [ライセンス →](license.ja.md)

- 実際の Cloudflare Team Domain と Application AUD を設定し、JWT 検証が成功するまで公開 hostname は意図的に公開しません。
- Claude read-only job は read/search/web tool だけを提供します。通常の conversation turn はそれらを明示許可した `dontAsk`、明示的な計画だけが `plan` mode を使います。
- External Claude session は閲覧専用で、Workhouse から resume、fork、stop できません。
- Codex 登録は eventual consistency です。新しい job は `pending` の後、bounded reconciliation で `unknown` になる場合があります。手動 refresh は重複 job を作らず再確認します。
- Workhouse 所有 Codex/Claude task detail は SSE Live です。所有していない external CLI/VS Code Codex と external Claude output は偽の Live ではなく Delayed polling または History と表示します。
- Browser approval UI と server path は `accept`、`acceptForSession`、`decline` を扱います。Playwright は local Codex Push deep link と三つの control、server／認証 Desktop Worker fixture は task/host/workspace/risk、expiry、duplicate、remote 400/409 error、`HOST_OFFLINE` を検証します。ただし将来の全 app-server version や approval method を保証しません。Native runtime が decision を広告する必要があり、effective policy が `never` の mode は interactive approval を出しません。
- Quota-reset reservation は待機中の server restart を生き残り、古い `claiming`/`starting` row は bounded pump で reconcile します。Provider launch 開始と task row 永続確定の間に server が停止した場合、重複実行を避けるため reservation を failed とし自動 retry を止めます。Provider に既に開始済み task がないことを確認後、reservation card から明示的に waiting queue へ戻せます。
- 確認済み Workhouse 所有 Worker process loss は task detail でレビュー可能な明示 resume として提示します。Preview は元の Provider thread、host、Workspace、model、permission boundary を固定し、現在 host は権限を下げることだけができます。公式 resume の失敗を新規 session で置き換えません。Completed、明示 failed、user-stopped、external、ambiguous、already-resumed、superseded task には提供しません。Restart 時は attempt metadata が link を証明すれば保存済み resumed task へ reconcile し、それ以外は uncertain failure として自動 retry を止めます。DB/browser fixture は restart、同時 click idempotency、境界表示、Worker restart 分類、local Claude `unknown`、不一致 remote thread 拒否を扱いますが、実 NAS power loss を両 Provider runtime で試してはいません。
- Full-history search は native Codex `thread/search` と安全に保存された Workhouse Codex/Claude field を統合します。NAS SQLite 3.40.0 は FTS5 がないため stored task は `updated_at, id` index cursor で source page ごとに最大 2,000 row を調べます。Title、prompt、final result、stored error を読み、task log や Provider transcript file は読みません。Match のない page に古い cursor が残る場合があり UI で区別します。Query は最大 500 result、memory cursor は 10 分または server restart で失効します。Paging 中に更新された row は cursor より前へ移動し得るため fresh snapshot には query を再開してください。Fixture は unloaded older Claude task、決定的 merge order、韓国語と `%_` literal、Provider/Workspace/status/date filter、bounded scan、output card jump を扱います。External Claude CLI は安全な保存 history がなく除外し、external Codex は native search API を使います。Test runtime の native Codex は `running`/`unknown` だけを返すため、runtime が field や turn content を省略すると completed/failed filter と正確な card は保証できません。
- Full-history search に collaboration/debate title は含まれません。Stored-task scan は query ごとに 50,000 candidate で停止します。Native Codex search は共有 app-server connection が warm の場合だけ使い、短い budget connection が他 view を妨げないようにします。Cold/unavailable の場合は cached-title fallback と UI に表示します。
- Custom prompt preset は個人サーバー設定で最大 20 件、label 40 Unicode 文字、prompt 4,000 Unicode 文字です。長い prompt は説明付きで拒否し builtin preset は保存しません。Device は server が空で prior snapshot もない場合だけ旧 `deck-prompt-presets` を migration します。その後の双方の変更は server value または merge を明示選択し、last snapshot で双方の削除を保持し、同じ ID の編集衝突は server が勝ちます。Merge limit／deletion exclusion は保存前に表示します。不正保存値は原値と revision を `ui.prompt-presets.corrupt-backup` に保持し CAS update で salvage、audit に件数を記録します。Sync は app 起動、task creation を開く時、visible browser が foreground に戻る時に実行し background push はありません。自動 upload failure には短い cooldown があります。Browser fixture は独立 desktop/phone/tablet context で migration、conflict merge、open device refresh、HTTP failure key replacement、lost-response idempotency を扱いますが、物理 Safari/Android 検証ではありません。
- PWA share intake は title、text、URL、許可 attachment を opaque expiring token の背後に保存し、task を開始せず editable draft を開きます。未使用 attachment は token expiry で削除し、使用 file は既存 7 日 upload cleanup と type/size restriction に従います（現在許可される executable/script type を含む）。Unit fixture は same-origin／OS document navigation metadata、cross-site rejection、manifest、draft conversion、Playwright は browser draft flow を扱います。実 Android/iOS share sheet や production Cloudflare Access では試しておらず device header と Access cookie は未確認です。
- Pull request 作成は登録 Workspace の completed Workhouse-owned task に限定します。実行 host で GitHub CLI auth、GitHub remote、named head branch、upstream/push state、open PR、ユーザー編集 base branch を再確認し、push、merge、review、force-push はしません。Outcome draft に機密 task 内容があり得るため公開前にユーザーが確認し明示承認する必要があります。Server idempotency と process 内 task lock は重複 click を防ぎますが crash 後は lock が残りません。不確実な `gh pr create` 後は open-PR query で既存 PR を再利用します。Unit test は fake `gh` で実 PR を作りません。Mobile fixture は確認と応答を扱いますが remote Worker は protocol/unit coverage のみで、C6 PR command を広告する Worker version が必要です。
- Codex 0.144.1 は tested thread/turn response で確定 effective model/effort/service-tier を公開しません。Workhouse は requested 値を表示し effective は「unconfirmed」とします。
- Codex 0.144.1 では登録済み `thread/items/list` が未対応のため turn pagination を使います。
- 既存 `cx doctor` failure 5 件は Workhouse 範囲外の古い dead-broker record です。Core version/hash/isolation/routing check 14 件は成功しており、この変更はその record を削除・非表示にしません。
- メインサーバーには Linux または Linux ベース NAS の Docker 配布を推奨します。Windows x64 portable server は互換性のための代替であり、意図的に未署名の portable ZIP と SHA-256 sidecar を提供します。Authenticode の発行者 ID は提供しないため、SmartScreen に Unknown publisher が表示される場合があります。Stable promotion 前に clean non-admin Windows 11 x64 VM で packaging、Defender/SmartScreen、NTFS/ACL、redirected Downloads、Provider discovery/execution、interrupted update/rollback、first boot を実機検証する必要があります。
- Browser、Tunnel、Workhouse server restart 中も Worker process が生きていれば work は継続します。NAS power loss/reboot は実行中 process を終了します。Service と Worker 復帰後、確認済み recoverable interruption だけを上記 recovery action で手動 resume できます。DSM の `bin/boot-start.sh` task は [service 自体を起動](deployment.ja.md)しますが agent job を自動 resume しません。
- 再起動後に外部 URL が HTTP 502 なら local origin が down です。`node bin/claudex-workhouse.mjs status` と `curl -sS http://127.0.0.1:3410/api/health/live` を実行してください。通常は `Claudex Workhouse Startup` boot task がない、または無効です。`bin/boot-start.sh` で開始しタスクスケジューラを再確認します。
- PWA offline は app shell/error experience だけです。Task 内容や結果を offline reading 用に cache しません。
- DSM boot task 作成と Cloudflare dashboard 変更は管理者の手動操作が必要です。`esynoscheduler.db` は root 所有なので boot task は DSM UI で作成し、wrapper と docs は準備済みでも非特権 service account から登録を script 化できません。
