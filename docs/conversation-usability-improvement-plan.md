# 대화·작업 모드 사용성 개선 계획

상태: 구현 완료 — P0~P3 및 후속 관측성 개선 반영 (2026-07-28)

근거 세션: `89d22d96-0211-4cea-b1e3-2eef60d59e43`

작성일: 2026-07-28

## 구현 결과

- P0: 최초 요청과 후속 입력을 공통 사용자 카드로 표시하고 대화 구간의 시각적 위계를 강화했다.
- P1: VS Code 보조 확장에서 workspace·파일·선택 범위·선택 텍스트·진단을 URL fragment로 Workhouse에 넘기며, 앱에서 미리 본 뒤 작업을 확정한다. 작업 상세에는 실제 파일/명령 이벤트를 근거로 한 완료·실패 요약을 고정했다.
- P2: 완료·실패와 별개로 `사용자 입력 필요` push를 구분했고, 빠른 작업 진입, 기본/사용자 프롬프트 프리셋, 클릭해서 적용하는 실행 추천을 추가했다.
- P3: 대화 생성 시 결론 Markdown 의도와 상대 경로를 지정할 수 있다. 종료 후 별도 확인을 거쳐 첫 provider가 초안하고 둘째 provider가 원문과 대조·보완한 새 `.md` 파일만 workspace 안에 생성한다.
- 한 provider가 실패한 2인 대화는 가능한 경우 남은 provider로 축소 운행하며, 축소 상태에서는 2인 검토 결론을 생성하지 않는다.

VS Code 연동은 IDE 화면을 복제하는 패널이 아니라 Workhouse 작업 생성 화면으로 현재 편집 문맥을 안전하게 전달하는 얇은 보조 확장이다. 실행과 장시간 관측, 결과 확인은 기존 Workhouse 앱이 담당한다.

## 목표

최근 대화 세션에서 나온 개선 의견을 실제 제품 작업 단위로 정리한다. 첫 배포는 대화 모드에서 사용자의 발화가 모델 응답 사이에 묻히는 문제를 해결하고, 이후 단독 작업의 문맥 전달, 실행 상태 파악, 결과 정리와 재개 경험을 순서대로 개선한다.

기존 강점인 장시간 백그라운드 실행, NAS 원격 운용, 세션 기록과 재개, Claude/Codex 교차 검토는 유지한다. IDE 전체를 복제하기보다 “IDE나 사용자의 지시를 넘겨받아 오래 일하고, 과정과 결과를 명확히 남기는 작업자”라는 방향에 집중한다.

## 세션에서 확인한 문제

1. 대화 모드의 사용자 입력 카드가 모델 카드와 시각적으로 잘 구분되지 않는다.
2. 짧은 단독 수정은 현재 파일, 선택 영역, 커서 위치를 말로 다시 설명해야 해서 IDE형 도구보다 마찰이 크다.
3. 실행 중 누가 무엇을 하는지, 사용자의 답을 기다리는지, 왜 실패했는지를 한눈에 알기 어렵다.
4. 작업이 끝난 뒤 긴 기록에서 변경 파일, 핵심 변경, 테스트 결과를 다시 찾아야 한다.
5. 완료나 사용자 응답 필요 시점을 놓치지 않으려면 화면을 계속 확인해야 한다.
6. 자주 쓰는 요청을 매번 다시 작성해야 한다.
7. 대화의 결론을 신뢰할 수 있는 문서로 남기는 명시적인 마무리 흐름이 없다.

## P0 — 사용자 입력 카드 가시성

### 현재 원인

`CollaborationTimeline.svelte`는 일반 협업 입력과 대화 라운드 입력을 모두 `.collaboration-user`로 출력한다. 현재 `sessions.css`에서 이 카드는 모델 카드와 동일한 `var(--surface)` 배경과 `var(--line)` 테두리를 사용하고, 본문 크기도 `0.78rem`이어서 감정 이미지와 큰 헤더를 가진 모델 응답 카드 사이에서 시각적 우선순위가 낮다. 대화 라운드에는 위쪽 여백만 추가되어 사용자 발화가 새 대화 구간의 시작이라는 점도 충분히 드러나지 않는다.

### 설계

- 사용자 입력을 공통 `ConversationUserCard` 컴포넌트로 분리해 최초 요청과 후속 라운드가 같은 구조와 접근성 규칙을 사용하게 한다.
- 카드에 색상 외의 식별 수단을 함께 둔다.
  - 사용자 아이콘 또는 고정된 “내 입력” 표식
  - 사용자 이름
  - 라운드 번호
  - 전송 시각
- 모델 카드와 구별되는 강조 배경, 굵은 측면 accent, 한 단계 강한 테두리를 사용한다. 색만으로 상태를 전달하지 않으며 밝은 테마와 어두운 테마 모두 기존 토큰에서 파생한다.
- 본문은 모델 대사와 동등하거나 조금 큰 읽기 크기와 충분한 행간을 적용하고, 긴 한국어 문장·줄바꿈·긴 경로가 넘치지 않게 한다.
- 각 후속 입력 카드는 해당 라운드의 명확한 시작 구분선 역할을 하게 한다. 별도의 장식용 relay 문구가 사용자 카드보다 먼저 눈에 띄지 않도록 위계를 조정한다.
- 성격 리마인더 배지는 보조 정보로 유지하되 사용자 이름과 본문보다 강하게 보이지 않게 한다.
- 데스크톱에서는 전체 타임라인 폭을 유지해 긴 요청의 가독성을 확보하고, 모바일에서는 좌우 정렬 트릭 대신 동일한 강조 구조를 유지한다.
- 서버 저장 형식, 메시지 순서, 라운드 계산, provider relay에는 손대지 않는다.

### 대상 파일

- `app/src/web/CollaborationTimeline.svelte`
- 새 `app/src/web/ConversationUserCard.svelte`
- `app/src/web/sessions.css`
- 필요한 경우 `app/src/web/i18n/ko.ts`, `en.ts`, `ja.ts`

### 완료 조건

- 최초 요청과 모든 후속 사용자 입력이 동일한 사용자 카드로 표시된다.
- 모델 카드가 연속된 긴 대화에서도 사용자 발화를 스크롤 중 즉시 식별할 수 있다.
- 사용자 이름, 라운드, 시각, 본문, 리마인더가 작은 화면에서도 겹치거나 잘리지 않는다.
- 밝은/어두운 테마와 320px 폭에서 텍스트 대비와 포커스 표시가 유지된다.
- 색상을 제거한 상태에서도 아이콘·레이블·구조만으로 사용자 카드임을 알 수 있다.

## P1 — 단독 작업 진입과 관측 가능성

### 1. 선택 영역을 작업으로 보내기

- VS Code에서 현재 workspace, 파일 경로, 선택 범위, 선택 텍스트, 진단 정보를 명시적인 미리보기와 함께 새 작업에 전달한다.
- “추천은 앱이, 확정은 사용자” 원칙을 적용해 전송 대상 모델과 포함할 문맥을 사용자가 확인하게 한다.
- 선택 텍스트가 없을 때는 파일과 커서 위치만 보내며, 비밀 파일과 workspace 밖 경로는 기존 접근 계약을 그대로 따른다.
- 기존 `workspace-file-editor-plan.md`와 겹치는 파일 탐색·편집 범위는 재사용하고, 별도 문맥 전달 포맷만 정의한다.

### 2. 실행 상태를 한 문장으로 표시

- 각 작업자를 `작업 중`, `사용자 입력 대기`, `실패`, `완료`의 안정된 상태로 요약한다.
- 상태에는 현재 단계와 마지막 갱신 시각을 붙이고, 원시 이벤트 로그는 펼쳐보는 보조 정보로 둔다.
- 실패 시 오류 로그보다 먼저 “왜 멈췄는지” 한 줄과 가능한 다음 행동을 표시한다.
- 한 provider가 실패해도 가능한 경우 살아 있는 provider로 축소 운행하거나 독립 재시도할 수 있음을 명확히 표시한다.

### 3. 완료 요약과 재개

- 완료 화면 첫 영역에 `변경 파일`, `핵심 변경`, `테스트 결과`를 고정된 구조로 요약한다.
- 요약은 실제 diff와 실행 기록을 근거로 만들고, 확인되지 않은 테스트를 성공으로 표시하지 않는다.
- `같은 세션에서 이어서 시키기`와 `다른 모델에게 독립 검토 요청`을 서로 다른 행동으로 제공한다.

## P2 — 맡겨두기와 반복 작업

### 알림

- 작업 완료, 사용자 입력 필요, 복구 불가능한 실패만 기본 알림 후보로 삼는다.
- 같은 상태의 중복 알림을 억제하고 세션으로 바로 이동하는 링크를 제공한다.
- 앱 내 알림을 먼저 안정화한 뒤 기존 push 구독 기반의 모바일 알림을 연결한다.

### 요청 프리셋

- `버그 수정`, `검토`, `테스트 실행` 같은 사용자 정의 요청 프리셋을 제공한다.
- 프리셋은 prompt 초안일 뿐 모델, 권한, workspace를 몰래 변경하지 않는다.
- 실행 전 최종 prompt와 대상 설정을 편집할 수 있게 한다.

## P3 — 대화 결론 Markdown

### 흐름

대화 생성 시 선택 가능한 `종료 후 Markdown 남기기` 옵션을 둔다.

1. 사용자가 저장 workspace, 상대 경로, 파일명을 확인한다.
2. 마지막 정상 라운드 뒤 첫 화자가 대화의 합의점, 이견, 결정, 후속 작업을 초안으로 작성한다.
3. 두 번째 화자가 원문 대화와 초안을 대조해 빠진 내용과 잘못된 우선순위를 수정한다.
4. 최종 문서에는 작성자/보완자, 근거 세션 ID, 작성 시각을 기록한다.
5. 보완자는 단순 승인만 하지 않고 변경한 문단마다 짧은 수정 이유를 남긴다.

### 안전 조건

- 대화 모드의 현재 read-only 계약을 옵션 하나로 우회하지 않는다. 문서 쓰기는 별도의 명시적 write 단계와 사용자 확인을 거친다.
- 절대 경로, workspace 밖 경로, 기존 파일 덮어쓰기는 현재 파일 접근 정책과 충돌 시 중단한다.
- 한 provider가 실패하면 초안만 최종본으로 가장하지 않고 `보완 미완료` 상태로 남긴다.
- 모델의 자유 형식 Markdown을 바로 신뢰하지 않고 고정 섹션과 provenance를 서버에서 검증한다.

## 구현 순서

1. 사용자 입력 카드 컴포넌트와 스타일을 구현한다.
2. 카드 렌더링·접근성·반응형 회귀 테스트를 추가하고 실제 긴 대화 fixture로 시각 검증한다.
3. 단독 작업의 VS Code 문맥 전달 계약과 미리보기 UI를 설계·구현한다.
4. 상태 요약, 실패 이유, 완료 요약, 재개/독립 검토 행동을 연결한다.
5. 알림과 요청 프리셋을 추가한다.
6. 쓰기 권한 경계를 별도로 설계한 뒤 두 단계 Markdown 결론 생성을 추가한다.

P0는 저장 구조나 provider 실행을 바꾸지 않는 독립적인 UI 개선이므로 먼저 배포할 수 있다. P1 이후 항목은 기존 세션 상태·권한·relay 경계에 영향을 줄 수 있어 각각 별도 변경과 검증으로 나눈다.

## 검증 계획

### 자동 테스트

- round별 첫 `user-input`이 정확히 한 번만 렌더링되는지 검사한다.
- 최초 요청, 후속 입력, 리마인더 포함 입력, 긴 여러 줄 입력의 카드 내용을 검사한다.
- timestamp가 없는 과거 메시지에서도 카드 구조가 깨지지 않는지 검사한다.
- 사용자 입력 추가 후 기존 run key와 자동 스크롤이 중복되거나 잘못된 카드로 이동하지 않는지 검사한다.
- 영어·한국어·일본어 레이블과 긴 사용자 별칭을 검사한다.
- 후속 기능에서는 상태 매핑, 실패 이유 fallback, 완료 요약의 근거 유무, Markdown 두 단계 provenance를 각각 단위 테스트한다.

### 수동·시각 검증

- 밝은/어두운 테마, 320px/420px/데스크톱 폭에서 확인한다.
- 모델 응답 20개 이상과 사용자 후속 입력 여러 개가 섞인 긴 대화를 스크롤하며 식별성을 확인한다.
- 200% 확대, 키보드 탐색, 고대비/색각 구분이 약한 환경에서 레이블과 포커스를 확인한다.
- 입력 중, 모델 실행 중, 사용자 대기, 완료 상태 전환에서 카드 순서와 자동 스크롤을 확인한다.

## 범위 밖

- P0에서 대화 저장 스키마나 provider prompt를 변경하지 않는다.
- 사용자 카드를 채팅 앱처럼 오른쪽에 작게 몰아 긴 요청 폭을 줄이지 않는다.
- 자동 모델 배차를 이번 계획의 선행 조건으로 삼지 않는다.
- Markdown 결론 기능을 대화 모드의 기존 read-only 권한을 우회하는 숨은 쓰기 경로로 만들지 않는다.
