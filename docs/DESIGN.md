# Claudex Workhouse 디자인 기준

UI를 새로 만들거나 고치는 모든 에이전트(Claude, Codex, 그 밖의 위임 대상)는
마크업이나 CSS를 쓰기 전에 이 문서를 읽는다. 기준 구현은
`app/src/web/styles.css` 상단의 토큰 블록이다. 이 문서와 코드가 다르면
코드가 맞고, 이 문서를 고친다.

## 1. 작업 순서: 골격을 먼저 정한다

먼저 만든 구조에 이후 작업이 매몰되는 일을 막기 위한 규칙이다.

- **새 화면, 새 패널, 레이아웃이 크게 바뀌는 작업**은 디자인 담당(기본값 Claude)이
  먼저 골격을 만든다. 골격은 정보 위계, 마크업 구조, 상태별 모양(빈 상태, 로딩,
  에러, 좁은 화면)까지 포함한다. 정적 목업(`docs/mockups/`)이나 스타일만 입힌
  빈 컴포넌트여도 된다.
- 구현 담당(예: Codex)은 그 골격 안에서 로직, 데이터 연결, 서버 작업을 채운다.
  **골격의 구조나 시각 결정을 바꾸지 않는다.** 바꿔야 할 이유가 생기면 멈추고
  이유를 보고한다.
- 구현 담당에게 "UI 틀까지 알아서 잡아라"라는 식으로 맡기지 않는다. 이미 생긴
  틀은 검수 단계에서 뒤집기 어렵다.
- 마무리로 디자인 담당이 실제 화면을 스크린샷으로 검수한다. 이 NAS에서는
  `docs/WORKSPACE_RUNBOOK.md`의 Docker Playwright 경로를 쓴다. 다크와 라이트,
  데스크톱과 760px 이하 폭을 모두 확인한다.
- 기존 화면에 버튼이나 항목을 하나 더하는 정도의 작은 수정은 이 순서를 생략하고,
  아래 규칙만 지킨다.

## 2. 토큰: 새 값을 만들지 않는다

색, 간격, 반경, 글자 크기에는 아래 변수만 쓴다. 컴포넌트에 hex, px 간격,
임의 radius를 직접 쓰지 않는다. 필요한 값이 없으면 토큰부터 추가하고,
다크, 라이트, 시스템 라이트 세 블록을 모두 채운다.

| 용도 | 토큰 |
|---|---|
| 배경 층 | `--bg` → `--surface` → `--surface-2` → `--surface-3` (깊어질수록 한 단계씩) |
| 구분선 | `--line`, 강조가 필요할 때만 `--line-strong` |
| 글자 | `--text`, 보조 정보는 `--muted` |
| 강조 | `--accent`, `--accent-strong`, 강조 위 글자는 `--on-accent`, 옅은 배경은 `--accent-soft` |
| 상태 | `--ok` / `--warn` / `--err`와 각각의 `-soft` |
| 프로바이더 식별 | `--provider-codex`, `--provider-claude`, … (프로바이더 구분에만 쓴다) |
| 간격 | `--space-1`(4) `--space-2`(8) `--space-3`(12) `--space-4`(16) `--space-5`(24) `--space-6`(32) |
| 반경 | `--radius-sm`(6) `--radius-md`(10) `--radius-lg`(14) `--radius-pill`. 카드와 컨트롤은 `--radius-card*`, `--radius-control*` |
| 글자 크기 | `--text-xs` `--text-sm` `--text-md` `--text-lg` `--text-xl` |
| 그림자 | `--shadow`(기본), `--shadow-lg`(떠 있는 팝오버·다이얼로그만) |
| 고정폭 | `--font-mono` |

테마 구조:

- **팔레트**(`data-palette`)는 `--accent`와 `--tint`만 바꾼다. 표면 전체가
  `--tint`로 살짝 물들기 때문에, 표면 색은 반드시 토큰을 거쳐야 팔레트를 따라간다.
- **스킨**(`data-skin`: elevated, outline, compact, terminal, flat)은 카드
  기하(`--card-*`, `--radius-card*`)만 바꾼다. 대화 카드 스타일은 `--card-*`
  변수로 쓰고 고정값을 박지 않는다. 그래야 다섯 스킨에서 모두 성립한다.
- 상태 색과 프로바이더 색은 팔레트가 바뀌어도 유지된다. 강조색으로 상태를
  표현하지 않는다.

## 3. 시각 원칙

- **조용한 기본값.** 표면 차이는 배경 한 단계와 1px `--line`으로 만든다.
  그림자, 그라디언트, 테두리 겹치기는 쓰지 않는다. 그림자는 떠 있는 레이어에만 쓴다.
- **강조는 화면당 한 곳.** `--accent` 채움 버튼은 그 영역의 주 행동 하나에만 쓴다.
  나머지 버튼은 `--surface-2` 배경이나 테두리만 있는 형태로 둔다.
- **위계는 크기보다 색과 굵기로.** 본문 대비 제목을 크게 키우기보다 `--text`와
  `--muted`의 대비로 위계를 만든다. 굵기는 앞으로 400(본문), 600(라벨·버튼),
  700(제목) 세 단계만 쓴다. 기존 650·750·800·850은 해당 영역을 손볼 때 이 세
  단계로 정리한다. 정리만을 위한 일괄 수정은 하지 않는다.
- **밀도.** 이 앱은 작업 도구다. 넉넉한 마케팅식 여백을 쓰지 않는다. 카드 안쪽
  간격은 `--card-padding`, 목록 행 간격은 `--space-2`~`--space-3`이 기본이다.
- **정보는 접어 둔다.** 자주 안 보는 세부 정보(로그, 메타데이터, 원문)는 접힘이나
  팝오버에 두고, 첫 화면에는 상태와 다음 행동만 둔다.
- **아이콘만 있는 버튼**에는 `aria-label`과 `title`을 단다.

## 4. 상호작용

- hover는 배경을 한 단계 올리거나(`--surface-2`→`--surface-3`) 테두리를
  `--accent`로 바꾸는 정도로 한다. 크기 변화나 이동은 쓰지 않는다.
- 포커스는 `:focus-visible`에 `outline:2px solid var(--accent)`를 쓴다.
  `outline:none`만 남기고 대체 표시를 빼먹지 않는다.
- 전환은 0.15s 안팎(`background`, `color`, `border-color`, `transform`)으로 짧게 한다.
  0.3s를 넘기거나 레이아웃 속성을 애니메이션하지 않는다.
- 위험한 행동은 `--err` 계열로 표시하고, 기존 확인 흐름(`danger-confirmation.ts`)을 쓴다.

## 5. 반응형

- 주 분기점은 `max-width:760px`(모바일)과 `max-width:1180px`(태블릿·좁은 데스크톱)이다.
  새 분기점을 만들기 전에 이 둘로 해결되는지 먼저 본다.
- 모바일에서 키보드와 뷰포트는 `--keyboard-inset`, `--viewport-height`,
  `--viewport-top`으로 처리한다. `100vh`를 직접 쓰지 않는다.
- 터치 대상은 최소 36px 높이를 확보한다.
- 화면 오른쪽 아래 떠 있는 컨트롤과 겹치지 않도록 `--floating-control-safe-right`를 따른다.

## 6. 문구와 다국어

- 화면에 보이는 문구는 전부 `app/src/web/i18n/{ko,en,ja}.ts`에 키로 넣는다.
  컴포넌트에 문자열을 직접 쓰지 않는다. 세 언어를 같은 커밋에서 모두 채운다.
- 짧고 구체적으로 쓴다. 버튼은 동사로 끝낸다("저장", "다시 시도").
  상태 문구는 무엇이 일어나고 있는지 쓴다("확인 중…", "응답 대기 중").

## 7. 위임 지시서에 넣을 문장

구현을 다른 에이전트에게 넘길 때 아래 문장을 그대로 붙인다.

> UI는 `docs/DESIGN.md`를 따른다. 제공된 골격의 마크업 구조와 시각 결정은 바꾸지
> 않는다. 색·간격·반경·글자 크기는 `styles.css`의 기존 토큰만 쓰고, 새 hex 값이나
> 임의 px 값을 넣지 않는다. 화면 문구는 ko/en/ja i18n 키로 추가한다. 골격을
> 바꿔야 할 이유가 생기면 바꾸지 말고 이유를 보고한다.
