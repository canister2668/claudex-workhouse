# 알려진 제한 사항

[English](known-limitations.en.md) · [한국어](known-limitations.ko.md) · [日本語](known-limitations.ja.md)

이전: [테스트](testing.ko.md) · [가이드북](guide.ko.md) · 다음: [라이선스 →](license.ko.md)

- 실제 Cloudflare Team Domain과 Application AUD를 설정하고 JWT 검증을 통과하기 전에는 공개 hostname을 의도적으로 게시하지 않습니다.
- Claude 읽기 전용 작업은 read/search/web 도구만 제공합니다. 일반 대화 turn은 이 도구를 명시적으로 허용한 `dontAsk`를 사용하고, 명시적인 계획 작업만 `plan` mode를 사용합니다.
- 외부 Claude session은 조회 전용이며 Workhouse에서 resume, fork, stop할 수 없습니다.
- Codex 등록은 eventual consistency 방식입니다. 새 job이 `pending`에 머물다 제한된 reconciliation 뒤 `unknown`이 될 수 있습니다. 수동 새로고침은 중복 job을 만들지 않고 다시 확인합니다.
- Workhouse 소유 Codex/Claude task detail은 SSE Live입니다. 소유하지 않은 외부 CLI/VS Code Codex와 외부 Claude 출력은 가짜 Live가 아니라 Delayed polling 또는 History로 표시합니다.
- Browser approval UI와 server path는 `accept`, `acceptForSession`, `decline`을 다룹니다. Playwright는 local Codex Push deep link와 세 control을, server/인증 Desktop Worker fixture는 task/host/workspace/risk, expiry, duplicate, 원격 400/409 오류, `HOST_OFFLINE`을 검증합니다. 그러나 모든 미래 app-server version이나 approval method를 보장하지는 않습니다. Native runtime이 decision을 광고해야 하고 effective policy가 `never`인 실행 mode는 interactive approval을 내보내지 않습니다.
- Quota-reset reservation은 대기 중 server restart를 견디며 오래된 `claiming`/`starting` row는 bounded pump로 reconcile합니다. Provider launch 시작과 task row 확정 사이에 server가 멈추면 중복 실행 방지를 위해 reservation을 failed로 두고 자동 재시도를 막습니다. Provider에 이미 시작된 task가 없는지 확인한 뒤 reservation card에서 명시적으로 waiting queue로 돌릴 수 있습니다.
- 확인된 Workhouse 소유 Worker process loss는 task detail에서 검토 가능한 명시적 resume으로 제공합니다. Preview는 원래 Provider thread, host, Workspace, model, permission 경계를 고정하며 현재 host는 권한을 낮추기만 할 수 있습니다. 공식 resume 실패를 새 session으로 대체하지 않습니다. Completed, 명시적 failed, user-stopped, external, ambiguous, already-resumed, superseded task에는 제공하지 않습니다. Restart 시 attempt metadata로 link가 입증되면 이미 저장된 resumed task로 reconcile하고, 그렇지 않으면 uncertain failure로 기록해 자동 재시도를 막습니다. DB/browser fixture는 restart, 동시 click idempotency, 경계 표시, Worker restart 분류, local Claude `unknown`, 잘못된 remote thread 거부를 다루지만 실제 NAS 전원 손실을 두 Provider runtime에서 시험하지는 않았습니다.
- 전체 history 검색은 native Codex `thread/search`와 안전하게 저장된 Workhouse Codex/Claude field를 합칩니다. NAS SQLite 3.40.0에는 FTS5가 없어 stored task는 `updated_at, id` index cursor로 source page당 최대 2,000 row를 봅니다. Title, prompt, final result, stored error를 읽고 task log나 Provider transcript file은 읽지 않습니다. Match 없는 page에도 오래된 cursor가 있을 수 있고 UI에서 별도로 표시합니다. Query당 최대 500개를 반환하고 memory cursor는 10분 또는 server restart에 만료됩니다. Paging 중 update된 row는 cursor 앞으로 이동할 수 있으므로 최신 snapshot은 query를 다시 시작하세요. Fixture는 unloaded older Claude task, 결정적 merge order, 한국어와 `%_` literal, Provider/Workspace/status/date filter, bounded scan, output card jump를 다룹니다. External Claude CLI는 안전한 저장 history가 없어 제외되고 external Codex는 native search API를 사용합니다. Native Codex가 tested runtime에서 `running`/`unknown`만 보고하므로 completed/failed filter와 정확한 card는 runtime이 field나 turn content를 생략하면 보장할 수 없습니다.
- 전체 history 검색에는 collaboration/debate title이 포함되지 않습니다. Stored-task scan은 query당 50,000 candidate에서 멈춥니다. Native Codex 검색은 공유 app-server 연결이 이미 warm일 때만 사용해 짧은 budget 연결이 다른 view를 방해하지 않게 합니다. Cold/unavailable이면 cached-title fallback임을 UI에 표시합니다.
- Custom prompt preset은 개인 서버 설정이며 최대 20개, label 40 Unicode 문자, prompt 4,000 Unicode 문자입니다. 긴 prompt는 설명과 함께 거부하며 builtin preset은 저장하지 않습니다. Device는 server가 비어 있고 prior snapshot도 없을 때만 기존 `deck-prompt-presets`를 migration합니다. 이후 양쪽 변경은 server 값 또는 merge를 명시적으로 선택하며 last snapshot으로 양쪽 삭제를 보존하고 같은 ID 편집 충돌은 server가 이깁니다. Merge limit·deletion 제외는 저장 전에 보여 줍니다. 잘못된 저장값은 원본과 revision을 `ui.prompt-presets.corrupt-backup`에 보존한 뒤 CAS update로 복구하고 audit에 개수를 기록합니다. Sync는 app 시작, task create 열기, visible browser foreground 복귀 때 수행하며 background push는 없습니다. 자동 upload 실패에는 짧은 cooldown이 있습니다. Browser fixture는 독립 desktop/phone/tablet context의 migration, conflict merge, open device refresh, HTTP failure key replacement, lost-response idempotency를 다루지만 물리 Safari/Android 검증은 아닙니다.
- PWA share intake는 title, text, URL, 허용 attachment를 opaque expiring token 뒤에 저장하고 작업을 시작하지 않은 editable draft를 엽니다. 미사용 attachment는 token 만료 때 제거되고 사용된 file은 기존 7일 upload cleanup과 type/size 제한을 따릅니다(현재 허용된 실행·script type 포함). Unit fixture는 same-origin/OS document navigation metadata, cross-site 거부, manifest, draft conversion을, Playwright는 browser draft flow를 다룹니다. 실제 Android/iOS share sheet나 production Cloudflare Access에서는 검증하지 않아 device header와 Access cookie는 미확인입니다.
- Pull request 생성은 등록 Workspace의 완료된 Workhouse 소유 task로 제한됩니다. 실행 호스트에서 GitHub CLI auth, GitHub remote, named head branch, upstream/push 상태, 열린 PR, 사용자가 편집한 base branch를 다시 확인하며 push/merge/review/force-push는 하지 않습니다. Outcome draft에는 민감한 task 내용이 있을 수 있어 게시 전 사용자가 확인하고 명시적으로 승인해야 합니다. Server idempotency와 process 내 task lock이 중복 click을 막지만 crash 후 lock은 유지되지 않습니다. 불확실한 `gh pr create` 뒤에는 open-PR query로 기존 PR을 재사용합니다. Unit test는 fake `gh`를 사용하고 실제 PR을 만들지 않습니다. Mobile fixture는 확인·응답을 다루지만 remote Worker는 protocol/unit coverage뿐이며 C6 PR command를 광고하는 Worker version이 필요합니다.
- Codex 0.144.1은 tested thread/turn response에서 확인된 effective model/effort/service-tier를 제공하지 않습니다. Workhouse는 requested 값을 표시하고 effective는 “unconfirmed”로 둡니다.
- Codex 0.144.1은 등록된 `thread/items/list`를 지원하지 않아 turn pagination을 사용합니다.
- 기존 `cx doctor` failure 5개는 Workhouse 범위 밖의 오래된 dead-broker record입니다. Core version/hash/isolation/routing check 14개는 통과하며 이 변경은 해당 record를 지우거나 숨기지 않습니다.
- 메인 서버는 Linux 또는 Linux 기반 NAS의 Docker 배포를 권장합니다. Windows x64 portable server는 호환성 대안이며 의도적으로 무서명 portable ZIP과 SHA-256 파일을 제공합니다. Authenticode 게시자 신원은 제공하지 않으므로 SmartScreen에 `알 수 없는 게시자`가 표시될 수 있습니다. Stable 승격 전에는 깨끗한 non-admin Windows 11 x64 VM에서 packaging, Defender/SmartScreen, NTFS/ACL, redirected Downloads, Provider 발견·실행, interrupted update/rollback, first boot를 실제 검증해야 합니다.
- Browser, Tunnel, Workhouse server restart 중에도 Worker process가 살아 있으면 작업이 유지됩니다. NAS power loss/reboot는 실행 중 process를 종료합니다. Service와 Worker 복귀 후 확인된 recoverable interruption만 위 recovery action으로 수동 resume할 수 있습니다. DSM `bin/boot-start.sh` task는 [service만 시작](deployment.ko.md)하고 agent job을 자동 resume하지 않습니다.
- 재부팅 뒤 외부 URL이 HTTP 502면 local origin이 down입니다. `node bin/claudex-workhouse.mjs status`와 `curl -sS http://127.0.0.1:3410/api/health/live`를 실행하세요. 보통 `Claudex Workhouse Startup` boot task가 없거나 꺼진 경우이며 `bin/boot-start.sh`로 시작하고 작업 스케줄러를 다시 확인합니다.
- PWA offline은 app shell/error 경험만 제공합니다. Task 내용과 결과는 offline reading용으로 cache하지 않습니다.
- DSM boot task 생성과 Cloudflare dashboard 변경은 관리자가 수동으로 해야 합니다. `esynoscheduler.db`가 root 소유이므로 boot task는 DSM UI에서 만들며, wrapper와 문서만 준비되어 있고 권한 없는 service account로 등록을 script화할 수 없습니다.
